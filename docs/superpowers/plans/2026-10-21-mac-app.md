# Mac App Implementation Plan

**Goal:** Double-click a Mac app to launch the local lead desk, setup and bounded research jobs.

**Architecture:** Reuse Node and the existing UI. A separate loopback server serves authenticated local job APIs. Jobs run in cancellable child process groups. A native Swift/AppKit app embeds WKWebView and launches a shell bootstrap without Terminal. Static Pages stays compatible.

## Tasks
- [x] Add a job manager and worker for setup, Harvey discovery and restricted Codex web research; preserve existing results and validate JSON before publication.
- [x] Add a loopback server with stable origin, HttpOnly session cookies, Host/Origin and custom-header checks, fixed routes, payload limits, one job at a time and timeouts. Test boundary rejection and lifecycle with fake workers.
- [x] Add a local-only control panel to the existing dashboard; pass register exclusions to research and review returned batches through normal import. Keep Pages free of local controls and candidate records.
- [x] Add a Finder-compatible launcher that locates runtimes, shows errors, detects its own service, opens a browser and supports quit/relaunch. Build an app into the user's Applications folder with no admin access.
- [x] Verify Node tests, browser flows with fake jobs, actual app opening, live discovery and bounded Codex research. Review tracked files; commit and push source and verify Pages deployment.

## Acceptance
`npm test`, `npm run build`, actual `open "$HOME/Applications/Kirat Lead Desk.app"`, authenticated local browser job checks. Confirm research uses sandboxed read-only execution and no unrelated user tools/config, and never sends outreach. Save all actual research and credentials outside Git.
